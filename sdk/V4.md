# SDK: configuration, content, native controls and provider contracts

This implementation is source/build/headless-test checked. Native UI/input and
Linux/Proton display behavior await live validation. It supplies provider contracts,
not a finished arbitrary game-object/material/editor/save API.

## Settings and authoring

Put `settings.schema.json` beside `mod.ini`. Core validates it before mod initialization;
the loader reads exactly the same file without executing the DLL. Invalid schemas or
persisted values block initialization with a status. Schema-free mods retain the INI path.

```json
{"version":1,"settings":[
  {"id":"enabled","type":"bool","default":true,"description":"Show the panel"},
  {"id":"distance","type":"int","min":1,"max":100,"default":10},
  {"id":"action","type":"keybind","section":"input","key":"my_mod.open","default":"Ctrl+F8"}
]}
```

Fields support bool/int/number/string/enum/keybind, defaults, section/key, min/max,
choices, description/category, restart and authority (`local` or `host`). Limits:
128 fields, 64 KiB schema, 4096-byte strings, finite numbers; integers are restricted
to the exact double range. Newlines/NUL cannot be injected into INI values.

`swml4::get/set` use JSON values and cache validated state. Set persists immediately;
reload validates the complete candidate before replacing the cache. Successful changes
queue copied `<owner>.settings.changed` JSON on the game lane. A committed change whose
queue is full returns `SWML_APPLIED_WITHOUT_EVENT`: reread state, do not repeat side effects.
Restart is metadata for the consumer to honor, not automatic mod reload.

Generate a standalone project:

```powershell
python tools/new_mod.py my_mod --output my_mod --settings --input --content --native-ui
cmake -S my_mod -B my_mod/build -G "Visual Studio 17 2022" -A x64
cmake --build my_mod/build --config Release -- /m:1 /nodeReuse:false
```

Flags compose; `--input` includes a schema keybind. The native-UI starter retains the
small container/label/button template; `examples/sdk_v4_tools` demonstrates new
checkbox/slider/edit-box settings and local commands. Examples start disabled.

## Actions and translations

`action_register` names the owner's action, native root class, key/modifiers and
optional held interval (50–60000 ms). Bindings persist under `[input] full.action.name`.
`action_rebind`, `action_cancel` and copied JSON `action_list` support editors/diagnostics.
Keybind-schema edits update registered actions. The initial path is keyboard/mouse.

The lazy native adapter observes the game's window messages and UI traversal. It
does not consume messages or poll global desktop keys. It blocks actions outside
the requested native screen, while text entry has focus or when window focus is lost.
Press/release/held callbacks are copied onto the game lane; no mod runs from WndProc.
No synthetic press is generated for a held key on focus regain. `input_generation`
is an input context epoch, not world identity. Native observation must first become
ready; registration and missing bindings report explicit results. Limit: 128 actions,
256 raw key events and 256 context observations per frame. Actions share the bounded
event queue; queue saturation can drop notifications, so avoid flooding consumers.
Stock-game binding conflicts/controller mapping and input consumption are not supplied.

Register at most 16 locales of 512 strings per owner. Translation fallback is exact
locale, base locale, then `en`. `{name}` substitutes scalar JSON arguments; `{{`/`}}`
escape braces. Strings are copied, bounded and mod-local. Stock localization replacement
and plural/gender rules are separate integrations.

## Content and assets

Schema subset: `type`, `enum`, `minimum`, `maximum`, `maxLength` (Unicode code points),
`maxItems`, `items`, `properties`, `required`, `additionalProperties` (boolean) and
`description`. Unsupported keywords are rejected at definition, including `$ref`.
No external schema resolution, automatic cross-entry reference validation, override
priority or native content application is implied. Consumers hash/pin authoritative
catalogues and validate references at a load boundary before use.

Limits: 256 registries, 4096 total entries/512 per contributor, 4 MiB per owner and
32 MiB shared metadata. JSON input is bounded to 1 MiB, depth 32 and 16384 nodes;
individual metadata calls use tighter limits. Numbers use double. For exact uint64
quantities use decimal strings with `swml_math::parse_uint64` or binary message fields.

`asset_read` reads at most 1 MiB from the caller's `assets/` tree. Traversal and
reparse points are rejected. This is a convenience boundary for trusted native mods,
not a sandbox capable of containing arbitrary DLL code.

## Native game UI

Create controls inside the owning UI callback with `ui_control_create`; value get/set
uses JSON bool/number/string. `SWML_UI_CHANGE` is deferred until after native traversal.
Programmatic writes update the change cache and do not synthesize user events. Each
root allows 256 controls; teardown invalidates handles and removes owned descendants.
Only SDK-created controls support value access.

Current constraints: checkbox bounds are square; sliders require width > height and
finite bounded range; enabled must be true at creation. Control resizing and dynamic
disable are unavailable; position/anchor and visibility work through retained accessors.
Edit boxes default to printable ASCII filtering and 255 bytes (configurable to 4096).
Input filter and limit apply to native typing; API writes validate length and string
shape but are not filtered character by character. Constructors consume native temporary
strings according to their audited ownership. Dropdowns/tooltips/scrolling and a general
layout library remain further native work. Do not treat an example panel as a universal
in-game settings browser.

## World context and persistence

Native providers claim disjoint fields with `context_bind` and publish verified
MODE/WORLD_ID/ROLE/TIME/SAVE_EPOCH values. Consumers request all required fields;
missing evidence yields `SWML_UNAVAILABLE`. Core assigns a local generation when
world identity changes and invalidates dependent fields. Old-generation writes fail.
`swml.world.context` carries deferred copied snapshots; use revision to deduplicate.
This is a context snapshot, not a guaranteed save-completion barrier.

World storage requires WORLD_ID and host/local ROLE plus the current generation.
Files are owner/world-keyed, up to 1 MiB, with nonzero schema version and CRC over
header+payload. Writes preserve a valid prior backup, flush and replace the active file.
Reads report schema mismatch explicitly for caller migration, or `SWML_RECOVERED_BACKUP`
when returning the prior valid copy. Never discard that result as an ordinary error.
Clients cannot write host state. This does not coordinate with a native Stormworks save,
and cannot provide atomic inventory debit + vehicle spawn + checkpoint durability.

## Multiplayer and numeric helpers

`message_codec.h` supplies fixed little-endian request/reply/error/snapshot frames,
schema/operation IDs, uint64 correlation, world UUID, application session epoch and
revision. The 56-byte header leaves 840 bytes within the existing 896-byte transport
limit. The bounded 128-request correlation table matches the actual transport peer
identity and local connection generation, expires requests and supports cancellation.
Drive it on the game lane. It adds no threads, receive owner or transport polling.

`checked_math.h` performs unsigned add/subtract and exact 128-bit intermediate
multiply/divide using portable 64-bit operations. Overflow/zero division leaves the
output unchanged; callers select rounding up/down. Domain units, residuals and
conservation policy belong to the resource adapter.

## Diagnostics and release status

Windows x64/MSVC binaries remain the target; Linux uses these through Steam/Proton.
The Linux scripts and Win32 paint changes are implemented, but compositor behavior,
native controls/input, real multiplayer and gameplay overhead need runtime evidence.
The approved plan's further native providers, richer UI controls, service/game-build
manifest requirements, atomic game-data overlays and snapshot streaming remain tracked
work. Code/build success does not make those features available.
